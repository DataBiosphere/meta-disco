The Comparability Gap

The concern was that we lack the metadata for any accurate cross-dataset analysis. Measured against our own corpus, that is right about the catalogue and wrong about the files — and the difference determines what to do about it.

01

The verdict, up front

From AnVIL's catalogue

0%

Donor sex, ancestry, biosample type, anatomical site, diagnosis, and activity assay type are null on every indexed row. Nothing in the catalogue supports a comparability judgement.

From the aligned-read files

98–100%

Reference sequence checksums, platform, platform model, library, sequencing centre and sample identifier are all present in headers we already fetch and cache.

1 of 12

Of the comparability-bearing fields available in-band, we use contig lengths for reference assembly. The rest are parsed and discarded.

So the concern is justified in its consequence and wrong in its cause. This is not an absence of metadata — for aligned reads it is an extraction gap, and the material is already on local disk. For assemblies and raw reads it genuinely is an absence, and that distinction should drive the response.

The single sharpest illustration follows.

  ANVIL_T2T                   LN=248,387,497   M5=8646cb1d7b7085a82d50bf991c0962c4

Two sibling workspaces from one consortium, differing by 169 bases on chromosome 1 and by a completely different sequence checksum, both reported as CHM13. The checksum that distinguishes them is present in 98–100% of those files and is the SAM specification's own mechanism for exactly this purpose.

02

Six hazards

Every cross-study comparison fails in one of six ways. Each is illustrated below with a case from our own corpus rather than a hypothetical.

H1

Coordinate incomparability — positions do not mean the same thing

Different reference builds place the same locus at different coordinates. This is the hazard people know about, and it is still routinely mishandled, because the failure is silent: both files have a chr1 and both have a position 1,000,000.

The subtle form is worse than the obvious one. GRCh38 versus CHM13 is caught by anyone paying attention. GRCh38 with an alt/decoy analysis set versus GRCh38 without is not — same coordinates, different mapping behaviour, because decoys absorb reads that would otherwise mismap.

In our corpus: 7 distinct reference files collapse into 2 enum values (#340)
H2

Processing incomparability — same coordinates, different sensitivity

Two call sets over identical samples and identical references still disagree if produced by different aligners, caller versions, or filtering regimes. A variant absent from one set may be absent because it is not there, or because that pipeline could not see it.

This is the hazard most likely to be attributed to biology. A comparison that varies pipeline and reference together will report the sum as a reference effect.

In our corpus: GATK 3.5 + VQSR vs GATK 4 gVCF; bwa 0.7.15 vs 0.7.17 vs Winnowmap (#341)
H3

Measurement incomparability — the assay did not ask the same question

WGS, exome and targeted panels differ in what they can observe. In exome data, "no variant" outside the capture region means "not examined", not "not present" — and the capture kit defines that region, so two exomes with different kits are not directly comparable either.

Depth compounds it: 4× and 30× coverage of the same genome yield different sensitivity, particularly for heterozygous sites and anything structural. Platform chemistry differs in error profile by sequence context, which is precisely what donor-specific benchmarking exists to measure.

Available in @RG: PL, PM, LB, CN, PU, DT — 100% populated, entirely unused
H4

Biological incomparability — the material was not the same

A lymphoblastoid cell line is not blood, and neither is liver. LCLs are EBV-transformed and accumulate culture-acquired variation, so a variant present in an LCL and absent in primary tissue from the same donor may be a culture artefact rather than a discrepancy in calling.

For expression, tissue identity dominates everything else. Comparing RNA across anatomical sites without recording the site is not a comparison at all.

In our corpus: MAGE is LCL RNA, 1000G is LCL DNA, GTEx is tissue — biosample_type is null on every AnVIL row
H5

Cohort incomparability — the people were chosen differently

Allele frequencies differ between a population reference panel and a disease case-control collection for reasons that have nothing to do with technology. Ascertainment is a property of the study, invisible in any file, and recoverable only from study-level metadata or the paper.

Relatedness matters too: 1000G's expanded release includes 602 trios, so treating its samples as independent observations overstates the effective sample size.

Recoverable from the marker paper or the 1000G panel — not from AnVIL
H6

Identity incomparability — the identifier denotes different things

The most insidious, because joins appear to succeed. A sample identifier, an aliquot identifier and a participant identifier are not interchangeable, and one person may contribute many of each. The 1000G NA/HG identifiers are Coriell cell-line identifiers, and cell line is not person.

The failure mode is a join that silently multiplies rows, or one that looks clean because both sides used the same string for different concepts.

In our corpus: @RG SM holds HG00096 in 1000G, "Bio Sample 1" in HPRC, run identifiers in HPRC_R2

Note the asymmetry between the two tables. CRAM carries an exact reference identity and VCF does not — the md5 attribute of ##contig is optional in the VCF specification and is populated on none of our 203,719 cached headers. For VCF, length is the only in-band signal, and it does separate the two CHM13 builds (248,387,497 versus 248,387,328) provided the lookup table knows both.

Raw reads — FASTQ

Almost nothing is in-band. The read-name grammar yields instrument and run identifiers, which is why platform is recoverable, but library strategy, target region, reference and sample identity are not present in the file at all. FASTQ comparability is an import problem by construction — this is the content ceiling ADR-0001 already records for modality and assay.

The authority is the archive record: ENA and SRA expose library_strategy, library_source, library_selection, library_layout and instrument_model as controlled vocabularies, which is exactly the H3 field set. For 3,202 T2T participants that record is reachable today by run accession.

Assemblies — FASTA

Nothing in-band. FASTA has no header block, so assembler, polisher, phasing method, input read technology and coverage are all absent. For HPRC the only in-file signal is the name (hprc_r2_v1.0.1, pat/mat versus hap1/hap2).

Assembly comparability therefore rests entirely on external catalogues. It is the clearest case in the corpus where import is the only route.

04

Standards exist, and they are not being used

The answer to “are there standards here?” is yes, and more than one for every hazard. The gap is adoption, not specification.

HazardStandardWhat it givesStatus here
H1 coordinates GA4GH refget · SAM @SQ M5 · GCA/GCF accessions Exact sequence identity by checksum — the definitive answer, not an inference present in files, unused
H1 variant identity GA4GH VRS Normalised, computable variant identifiers so the same event matches across systems not in scope today
H2 processing SAM @PG · VCF ##source Tool, version and command line as a provenance chain present in files, unused
H3 measurement SRA/ENA library_* + instrument_model Controlled vocabulary for strategy, source, selection, layout, platform reachable by accession, not imported
H4 biological UBERON · OBI/EFO · BioSample/MIxS Ontology-coded anatomical site, cell type and assay null in AnVIL; GTEx portal supplies UBERON
H5 cohort GA4GH Phenopackets v2 · DUO Subject, phenotype and consent exchange with defined semantics phenopacket facet exists, 100% empty
H6 identity AnVIL TDR model · DRS Distinct donor, biosample and file entities with typed relations modelled, unpopulated, ids per-snapshot
cross-dataset query GA4GH Beacon v2 Federated variant discovery with agreed response semantics not applicable until the above exist

Two observations worth separating out. First, every H1 and H2 answer is already inside the files — refget-style checksums and provenance chains are not aspirational, they are populated at 98–100% and being discarded at parse time. Second, every H4, H5 and H6 answer requires someone else to act: those are catalogue fields AnVIL models and does not fill, or external registries we would need to import.

That is the practical split. Half the problem is ours to fix this quarter; half is a data-provider conversation.

05

Use-case checklists

What each common cross-study analysis actually requires, and whether it is currently possible on AnVIL open data.

A. Joint variant analysis across cohorts

Merge variant calls from two or more studies into one analysis set — to gain power for association testing, or to build a reference allele-frequency panel that spans more ancestries than any single cohort covers.

in per-study callsets over overlapping or disjoint samples  →  out one merged callset whose genotypes and frequencies mean the same thing on every row

  • identical reference build — checksum-verified, not name-matched (H1)
  • identical or deliberately harmonised calling pipeline (H2)
  • same assay and comparable depth; capture regions intersected for exomes (H3)
  • normalised representation — left-aligned, multi-allelics split (H2)
  • relatedness and ascertainment known before frequencies mean anything (H5)
Not currently safe. Reference identity is name-matched and pipeline is unrecorded.

B. Benchmarking a pipeline against truth

Measure what a variant-calling pipeline gets right and wrong, broken down by how hard each region is — so the answer is actionable rather than a single genome-wide number.

in a query callset · an independent truth set · its confident regions  →  out recall and precision per region class

  • truth and query on the same reference build (H1)
  • truth generated independently of the pipeline under test (H2)
  • confident regions stated explicitly, not assumed genome-wide (H3)
  • stratification by region class, or the headline number misleads (H3)
Feasible today — this is use case 1, and the assembly truth is reference-free by construction.

C. Expression comparison across studies

Compare transcript or gene abundance between studies — for tissue-specific expression, or to replicate an eQTL in a second cohort. The whole difficulty is separating biological signal from protocol difference.

in quantified expression matrices · biosample and protocol annotation  →  out differential or correlated expression attributable to biology

  • anatomical site, ontology-coded (H4)
  • biosample type — primary tissue versus cell line is not a detail (H4)
  • library selection: poly-A versus ribo-depleted versus total (H3)
  • quantification reference and annotation version (H1)
  • batch and centre for any effect that survives normalisation (H3)
Not possible. Anatomical site and biosample type are null on every AnVIL row.

D. Cohort assembly for downstream analysis

Select the participants who meet a set of criteria and gather their files. This is the search itself, upstream of any analysis — and it is what every other use case on this page depends on.

in participant attributes · per-participant data availability  →  out a manifest of participants and files a workflow can consume

  • a participant identifier stable across datasets (H6)
  • data type and reference per artefact (H1)
  • consent and data-use terms travelling with the result (H5)
  • relatedness, so the cohort is not silently structured (H5)
Not possible. Donor identifiers are minted per snapshot.
06

What to do, in order

The one-line answer

Stop inferring the reference. Read the checksum.

Contig-length matching is an inference that collides across builds. @SQ M5 is an exact identity, present in 98–100% of our aligned reads, defined by the SAM specification and shared with GA4GH refget. Switching to it converts H1 from a guess into a fact, for the majority of the corpus, with no new fetches.

After that, in descending order of value per unit of work:

Extract the provenance we already parse — @PG and ##GATKCommandLine (#341). This does not fix H2, but it makes H2 visible, which is the difference between a user being warned and a user being wrong.

Import the archive record for FASTQ — ENA/SRA library_* and instrument_model is the H3 vocabulary, already reachable by run accession for 3,202 T2T participants. Mind the circularity rule: importing platform from ENA costs us ENA as an independent platform validator.

Ask AnVIL for a stable participant identifier — the H6 fix, and the one thing on this list we cannot do ourselves.

Treat H4 and H5 as import problems — biosample and cohort metadata are not in any file. GTEx's portal supplies UBERON-coded anatomical site for its 980 donors, which is the proof that import works where a consortium maintains a catalogue.

What this report does not establish

Coverage outside the datasets measured. The percentages come from cached evidence for seven AnVIL open-access datasets. Controlled-access datasets are absent from our corpus entirely, and their header conventions may differ.

That M5 is sufficient on its own. It identifies a sequence, not an analysis set — two references sharing every chromosome checksum could still differ in decoy and alt content. The full identity is the set of checksums, not one.

Standards detail. The standards above are named from working knowledge; versions and current specification details were not re-verified against their documents for this report. Confirm before citing any of it externally.

That extraction is in scope. Whether processing provenance belongs in meta-disco at all is an open ADR-0001 question (#341), deliberately not pre-answered here.

07

Glossary

The artefacts named as inputs and outputs above, and the properties that decide whether any two of them can be compared.

Inputs

callset
The variant calls for one or more samples against one reference, as a VCF. A per-study callset is what a single study deposited; it carries that study's caller, filters and reference, all of which travel with it.
gVCF
A callset that also records confidence at non-variant positions, so “no call here” can be told apart from “no data here”. Merging plain VCFs without it silently converts missing data into reference genotypes.
query callset
The calls being graded in a benchmark — the output of the pipeline under test.
truth set
Variant calls believed correct for the same sample, generated independently of the pipeline being tested. Independence is the whole point: a truth set sharing the query's aligner inherits its blind spots.
confident regions
The intervals over which a truth set claims to be complete, usually a BED. Outside them a disagreement is uninformative rather than an error, so a benchmark that ignores them reports noise as failure.
region class
(stratification)
A partition of the genome by difficulty — unique sequence, segmental duplications, tandem repeats, MHC, medically relevant genes. Short-read performance varies by orders of magnitude between them, so a genome-wide average describes none of them.
capture region
The intervals an exome or targeted panel actually assays. Outside them, absence of a variant means “not examined”. Two exomes with different capture kits are not directly comparable even at identical depth.
quantified expression matrix
Genes or transcripts by samples, holding abundance values. Comparable across studies only when the quantification reference and annotation version match.
biosample annotation
What the material was — anatomical site, whether primary tissue or a cell line, and how it was collected and preserved. The dominant variable in any expression comparison.
protocol annotation
How the library was made — selection (poly-A, ribo-depleted, total), strandedness, read layout and length. Protocol differences produce expression differences that look biological.
participant attributes
The properties a cohort query selects on: sex, ancestry, phenotype, family structure, consent terms.
data availability
For each participant, which artefacts exist and against which reference. This is the join that turns a list of people into an answerable query, and the thing AnVIL cannot currently express.

Outputs

merged callset
One callset spanning several studies in which a genotype means the same thing regardless of which study contributed it. Achieving that is the entire difficulty; concatenating files is not it.
allele frequency panel
Per-variant frequencies derived from a merged callset and used as a population reference. Valid only when ascertainment and relatedness are known — otherwise the frequencies describe the sampling, not the population.
recall · precision
The share of true variants a pipeline found, and the share of its calls that were true. Meaningful per region class and per variant class; misleading as a single number.
differential expression
A difference in abundance between conditions, tissues or cohorts that survives correction for protocol and batch. Without biosample and protocol annotation it cannot be distinguished from an artefact.
manifest
A table of participants and file locations — DRS URIs or signed URLs — that a workflow can consume directly. The deliverable of a cohort query.

Properties that decide comparability

reference build
A specific assembly release — CHM13 v2.0, GRCh38.p12 — not a family. Two builds in the same family have different coordinates.
analysis set
A packaging of a build with or without decoy contigs, alternate haplotypes and HLA sequences. Same coordinates, different mapping behaviour, because decoys absorb reads that would otherwise mismap.
decoy contigs
Extra sequences bundled with a reference that are not part of the assembly proper — in GRCh38's case hs38d1, built from sequence known to occur in human genomes but absent from the primary assembly. They exist as a sink: reads from that sequence land on the decoy instead of mismapping to a similar-looking location on a real chromosome, which suppresses false positive calls there. Adding or removing them changes what maps where without moving a single primary coordinate.
alternate haplotypes
(alt contigs)
Additional scaffolds representing population variation at loci too divergent for one linear path to describe — GRCh38 carries hundreds of them over its most structurally variable regions. A read may match the primary and an alt equally well, so the aligner has to be alt-aware; one that is not splits reads between the two copies, halving apparent depth and losing heterozygous calls at exactly the loci that most needed them.
MHC
(major histocompatibility complex)
A roughly 4 Mb stretch of chromosome 6 carrying the genes for immune self-recognition, and the most polymorphic region of the human genome. Some individuals' haplotypes diverge so far from the reference that their reads map poorly or not at all — which is why it appears as its own stratum in every serious benchmark rather than being folded into a genome-wide average.
HLA
(human leukocyte antigen)
The gene family inside the MHC — HLA-A, -B, -C for class I, HLA-DR, -DQ, -DP for class II. The two terms are not synonyms and this report should not have used them as such: MHC names the region, HLA names the genes within it and their alleles.
HLA sequences
(in an analysis set)
Separate contigs holding known HLA allele sequences, bundled with a reference so that reads from alleles unlike the primary assembly have somewhere to map. Without them those reads pile into the primary MHC and generate spurious variants; with them, which allele set was bundled changes MHC calling directly. The GRCh38 packaging observed in this corpus says so in its own filename — GRCh38_full_analysis_set_plus_decoy_hla.fa.
sequence checksum
(@SQ M5)
The MD5 of a reference sequence, carried per contig in a BAM or CRAM header. Identifies a build exactly instead of by name, and is the identity GA4GH refget is built on. Present in 98–100% of our aligned reads.
PAR
(pseudoautosomal region)
The stretches at each end of chrX and chrY that are identical between the two, and recombine like autosomes. Because the sequence is shared, a read from there matches both chromosomes equally well and an aligner has no principled way to choose.
PAR-masking
Replacing the pseudoautosomal region on chrY with Ns, so those reads land on chrX instead of being split arbitrarily between two copies of the same sequence. It changes coverage and genotypes across the region, and whether a reference is masked is not visible in its name — two references distributed under the same filename can differ in exactly this. In our corpus, Homo_sapiens_assembly38.fasta and chm13v2.0.fasta each appear with two different chrY checksums at identical chrY length, which is the signature of this difference. We record both checksums and draw no conclusion: confirming a mask means reading the sequence for those N-runs, which a header cannot do.
normalisation
Representing indels left-aligned and parsimoniously and splitting multi-allelic records, so that the same biological event compares equal between callsets. Un-normalised sets disagree on variants they both contain.
ascertainment
How participants were selected — population sampling, case-control, family-based. Determines whether an allele frequency is a population estimate or an artefact of recruitment. Invisible in any file.
relatedness
The presence of families within a cohort. 1000 Genomes' expanded release contains 602 trios; treating its samples as independent overstates the effective sample size.
